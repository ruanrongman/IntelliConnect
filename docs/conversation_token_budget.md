# 对话 Token 预算

普通聊天与 Function Calling Router 在发起模型请求前，使用完整输入（系统提示词、工具定义、历史和当前问题）决定是否压缩会话历史。

存在可用基准时，预算为：

```text
上一轮服务商返回的 prompt_tokens
+ 本轮完整输入的本地估算
- 上一轮完整输入的本地估算
```

真实输入包含缓存命中的 Token；不使用会话累计用量、输出 Token 或所有模型调用的最大值。时间、长期记忆、检索结果及新增消息的变化计入估算差额。压缩阈值和保留轮数仍由现有 `memory.summary-threshold-ratio`、`memory.recent-turns` 配置控制。

基准按模型客户端（供应商、模型及凭据）、产品、会话、调用组件和工具定义隔离。后台记忆/图谱提取不会覆盖聊天或路由的基准。基准在收到真实 usage 后更新；同步和流式调用均支持，流式调用在完成回调前更新。

首次调用、usage 缺失或输入为零、历史被裁剪/编辑、工具定义变化时使用本地估算兜底。每个模型客户端最多保留 256 个基准，48 小时后失效；仅保存内容指纹和计数，应用重启或基准被淘汰后重新采样。旧版分类器等没有完整请求预算的路径保留历史估算兜底。

这仍是请求前预算：服务商的真实用量在请求完成后才能取得，新增内容无法提前获得真实计数。如果固定提示词、当前问题或必须保留的最近轮次本身超过窗口，本策略无法仅通过删除旧历史解决。
